# Database Documentation — Farm Profile & Plantation Management System

**Database:** MongoDB (via Mongoose)
**Collections:** `users`, `farmers`, `plantations`, `plantationlocations`, `plantationimages`, `plantationactivities`

All schemas use `{ timestamps: true }`, so every document also has `createdAt` / `updatedAt`.

---

## 1. `users`  — `backend/models/User.js`

| Field | Type | Notes |
|---|---|---|
| `fullName` | String | required |
| `mobileNumber` | String | required, **unique** |
| `email` | String | required, **unique**, lowercased, validated format |
| `password` | String | required, min length 6, hashed with bcrypt on save, `select: false` (never returned by default) |
| `role` | String | enum: `field_user` (default), `admin` |
| `isActive` | Boolean | default `true` |

**Behavior:** `pre("save")` hook hashes the password whenever it changes. `comparePassword()` instance method checks a candidate password against the hash.

---

## 2. `farmers` — `backend/models/Farmer.js`

| Field | Type | Notes |
|---|---|---|
| `farmerName` | String | required |
| `mobileNumber` | String | required |
| `alternateMobileNumber` | String | optional |
| `gender` | String | enum: `Male`, `Female`, `Other` |
| `dateOfBirth` | Date | |
| `address.village` / `taluk` / `district` / `state` / `pinCode` | String | embedded sub-document |
| `primaryOccupation` | String | |
| `farmingExperienceYears` | Number | min 0 |
| `createdBy` | ObjectId → `User` | who created this farmer record |
| `isActive` | Boolean | default `true` — used for soft delete |

**Virtual:** `plantationCount` — computed via a virtual populate against `plantations.farmer` (not stored on the document).
**Index:** text index on `farmerName` + `mobileNumber` for search.

**Relationship:** one Farmer → many Plantations.

---

## 3. `plantations` — `backend/models/Plantation.js`

| Field | Type | Notes |
|---|---|---|
| `farmer` | ObjectId → `Farmer` | required |
| `plantationName` | String | required |
| `plantationCode` | String | required, **unique** |
| `plantationType` | String | e.g. Coconut, Areca, Coffee |
| `area` | Number | required |
| `areaUnit` | String | enum: `Acres` (default), `Hectares` |
| `numberOfPlants` | Number | min 0 |
| `address.village` / `taluk` / `district` / `state` | String | embedded sub-document |
| `irrigationMethod` / `waterSource` / `soilType` | String | |
| `plantationAgeYears` | Number | min 0 |
| `plantVariety` | String | |
| `createdBy` | ObjectId → `User` | |
| `isActive` | Boolean | default `true` — soft delete |

**Index:** text index on `plantationName` + `plantationCode` for search.

**Relationships:**
- many Plantations → one Farmer (`farmer`)
- one Plantation → many PlantationImages
- one Plantation → one current PlantationLocation (upsert model, not a history)
- one Plantation → many PlantationActivities

---

## 4. `plantationlocations` — `backend/models/PlantationLocation.js`

| Field | Type | Notes |
|---|---|---|
| `plantation` | ObjectId → `Plantation` | required |
| `latitude` | Number | required, range -90..90 |
| `longitude` | Number | required, range -180..180 |
| `capturedBy` | ObjectId → `User` | |
| `capturedAt` | Date | default now |

**Design note:** this is an **upsert-per-plantation** model — saving a new location for the same plantation overwrites the previous one (one "current" location, not a location history). If a history of GPS changes is ever needed, this would need to move to an append-only log instead.

---

## 5. `plantationimages` — `backend/models/PlantatationImage.js`
*(note: the file name has a typo — "Plantatation" — kept as-is since renaming would require updating every `require()` of it)*

| Field | Type | Notes |
|---|---|---|
| `plantation` | ObjectId → `Plantation` | required |
| `imageUrl` | String | required — relative path, e.g. `/uploads/plantations/<file>` |
| `category` | String | enum: `Plantation Overview`, `Plant Images`, `Irrigation Images`, `Other` (default) |
| `fileSizeBytes` | Number | |
| `uploadedBy` | ObjectId → `User` | |

Files themselves live on disk under `backend/uploads/plantations/` and are served statically at `/uploads/...`. Deleting an image record also deletes the file from disk.

---

## 6. `plantationactivities` — `backend/models/PlantationActivity.js`

| Field | Type | Notes |
|---|---|---|
| `plantation` | ObjectId → `Plantation` | required |
| `activityType` | String | enum: `Plantation Created`, `Plantation Updated`, `Area Modified`, `Plantation Photo Added`, `Location Updated`, `Other` |
| `remarks` | String | free-text detail, auto-generated by the API |
| `performedBy` | ObjectId → `User` | |
| `activityDate` | Date | default now |

**Behavior:** entries are written automatically by `backend/utils/logActivity.js`, called from the Plantation, Location, and Image controllers — there is no manual "add activity" endpoint by design.

## Entity Relationship Summary

```
User ──< createdBy ──< Farmer ──< farmer ──< Plantation
                                                  │
                        ┌─────────────────────────┼─────────────────────────┐
                        │                         │                         │
                        ▼                         ▼                         ▼
              PlantationLocation          PlantationImage          PlantationActivity
              (one current record)        (many per plantation)   (many per plantation)
```

- A `User` creates `Farmer` and `Plantation` records (`createdBy`) and performs actions logged against `PlantationActivity` (`performedBy`).
- A `Farmer` has many `Plantation`s (`Plantation.farmer`).
- A `Plantation` has one current `PlantationLocation`, many `PlantationImage`s, and many `PlantationActivity` entries.
